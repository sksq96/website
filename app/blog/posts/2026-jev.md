I quickly wrote a CLI to make it easier to test and run queries against Jev (from TypeSafe), for a few reasons.

1. I wanted to learn how to use Jev
2. I had some ideas about how to use it to improve my AI workflows
3. I wanted to test my ideas without writing much code
4. I wanted to see how quickly I could ship something usable with AI in a few hours

I'll explain why I think Jev is underrated for AI in a future post.

### What I knew, and what I didn't

Before I started, I knew that Jev was a fast, cheap, probabilistic model that could answer a few different types of queries.

But I didn't know:

1. How to make the best use of Jev
2. What types of queries to test
3. How to structure my experiments
4. How to use any of it for AI

I didn't have time to take a class on Jev or build a full AI agent to test it, so my goals were to quickly test some hypotheses. The quickest way I could do that was on the CLI.

### How I built the CLI

It's a single `.mjs` file which has all the functionality in it. I put it in a GitHub repo and then published it as an npm package.

To use Jev, you need an account with TypeSafe and you need an API key. The CLI lets you set this up and access the API.

But it also includes a bunch of other features:

1. It has structured outputs for the probabilities of answers in JSON or text format
2. It can take multiple questions and inputs and return answers in a single API call to Jev, which is cheaper and faster
3. You can specify the confidence level, e.g. get an error if the probability is less than 80%
4. It can take multiple inputs and return multiple outputs in a batch with a single command, using JSONL
5. It supports all the query types that Jev supports (noul, choice, score, box)
6. It has an MCP server that can be used with Claude Code or Codex to make Jev queries from within your agent workflows

I didn't know what features I needed until I started using it. I knew that I wanted to do some experiments with images, so I added the ability to query images. I knew that I wanted to be able to do batches of queries, so I added a `--jsonl` flag.

The most complicated part was probably the batch processing, because I had to deal with rate limits and retries. But Claude Code handled it for me, I just had to think through the design and types of queries I wanted to do.

### Learnings from building the CLI

The CLI has been a great way to get a feel for how Jev works and what it's strengths and weaknesses are. It's definitely not suitable for all types of tasks, but I'll talk about where it's particularly useful in a follow-up post.

The main thing I learned from building the CLI is that Jev is surprisingly capable. It's very fast and cheap, and I think it's been underused in AI workflows.

I also discovered that Jev is very sensitive to wording in the queries. I think that's mostly due to how the API is structured, but it means I would need to spend some time tuning the queries to get the best results.

Jev also has a somewhat complex nested JSON data structure that you have to construct to make queries. I didn't want to manually build these, so I made my CLI build them for me. But I also had to make a way to show the underlying JSON and the equivalent `curl` command so I could see what was actually being sent to the API.

The CLI has been a great way to quickly test out different queries and ideas. I'm glad I took the time to build it, because it's really helped me learn about Jev and I think it's a useful tool.
