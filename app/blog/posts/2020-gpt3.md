I decided to scratch the AI itch and start a GPT-3 project. In this post, I’ll document the process of setting up, training, and evaluating my GPT-3 model.

This post will be continuously updated until the conclusion.

### December 14 2020

I’ve been given access to the OpenAI monorepo for the purpose of this project. I was given a VM with 8 NVIDIA Tesla V100s and told to up the batch size until the VRAM is maxed out.

I got the model training, and the VRAM is doing just fine:

![](/images/gpt3_training_log_max_vram.png)

I’m using nvidia-smi to track the VRAM usage. I’m not sure why it’s not going past ~12GB when I have 32GB total. But I’m happy with this for now.

### December 15 2020

I switched over to 16GB V100s, since the 32GB version are in short supply. There’s a few extra lines of logging to make sure that the GPU is doing the work. I don’t want to leave the GPT-3 model idling at 100% GPU usage while all the work is done in the CPU.

![](/images/gpt3_training_log_cpu_usage.png)

### December 18 2020

I’m playing around with the generation feature of GPT-3. I’ll admit I’m not too familiar with the difference between batch size and context size, but I think it’s fun to see how it performs.

The 2.7B parameter model can generate decent sized paragraphs of text when given a line. I fed it “Many people believe that” and it generated the rest.

![](/images/gpt3_training_log_generated_text.png)

I’ll have to read more about the context size and figure out why I’m not able to generate larger chunks of text. 

I also found out that the way to monitor GPU usage was to use nvidia-smi --query-gpu=... --format=csv -l . The previous version shows the usage at the moment. This command will stream the GPU usage in the format I like.

### December 19 2020

I’m continuing to play around with text generation. The default parameters are context_tokens=n_ctx, batch_size=1. I’ve read a few lines in the GPT-3 paper and it seems that this is to generate the next predicted word. I figure that I can increase n_ctx = 100, batch_size = 5 to generate 5 different word predictions.

![](/images/gpt3_training_log_generated_text_batch.png)

### January 12 2021

I’m finally back. I’ve been busy with other projects, so I had to take a break from GPT-3. I’ll be picking it up again.

I’m planning on evaluating the 2.7B parameter model. I’ll use the RACE dataset to evaluate my model. GPT-3 was trained on a combination of webtext, wikipedia, bookcorpus, and webtext2. This dataset is a collection of passages and questions from English examinations.

### January 14 2021

I’ve managed to get the RACE dataset evaluation to work, but I think I’ve run into a bug.

![](/images/gpt3_training_log_loss_curve.png)

The loss for the model is decreasing, but the performance in the evaluation suite is worse than when I started. The loss is still decreasing, but it seems that the model is getting worse.

![](/images/gpt3_training_log_eval_metrics.png)

                       [--md MODEL_NAME MODEL_PATH]

                       [--append] [--single]
optional arguments:
  -h, --help            show this help message and exit

                        num examples to eval per checkpoint, 0 for all, -1 for

                        Batch size for eval. Memory usage is dominated by

And this is the command I’m using to evaluate the model:

```bash
python -m eval_suite.eval_lambada -m 2.7B_1x-2xsmall-j --max-ctx 1024 -n 500 -b 64
```

I’m confused as to why the performance gets worse as the loss decreases. I’ll try a different model and see if the same thing happens.
