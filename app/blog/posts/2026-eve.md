i made this because i was curious how harness like eve can be used to make agents. This is my attempt to use eve to make Hue.

I did not know what I was doing, but I was just trying to see if I can get the familiar tools and prompts of hue and put it into a harness like eve with Opus 5.5. 

My hypothesis was that the loop and harness is more important than the prompt and tools (though those are still important.)

```typescript
import { defineAgent } from 'eve';
import { anthropic } from 'eve/models/anthropic';

export default defineAgent({
  model: anthropic(process.env.EVE_MODEL ?? 'claude-opus-5'),
  compaction: { keepRecentTokens: 10_000 },
  modelContextWindowTokens: 100_000,
  modelOptions: {
    providerOptions: {
      anthropic: {
        effort: 'low',
        cacheControl: { type: 'ephemeral', ttl: '1h' },
      },
    },
  },
  disableTool('web_fetch'),
  disableTool('web_search'),
  disableTool('ask_question'),
  modelCallConcurrency: 1,
});
```

Here is the file for eve agent.ts (everything is in typescript.) I've set the model to opus5, set the compaction tokens to be 10k (this is how many tokens eve should store in context,) and set the context window tokens to be 100k (this is how many tokens eve can see in context, if you set to 1M, the context will get very long.) I chose to disable the default web_fetch and web_search tools and use the Exa ones I already had for Hue.

I use a modelContextWindowTokens of 100k tokens to ensure that there is a constant pressure on the LLM to compact its context. I think it helps make the agent smarter.

You can see in the repo, it's actually not a lot of code that you need to write.

I didn't implement it at first, but had to do it when I was trying to give Hue the ability to see images. I had to create a new tool called view_image that would allow Hue to view the image. I had to create a new file for the tool, but it's just a few lines of code to access the image and resize it to 1568px jpeg (which is the max size that Opus 5 can see.)

```typescript
import { defineTool } from 'eve/tools';
import { z } from 'zod';
import { bucketGetBytes } from '../lib/db.js';
import { normalizeRef } from '../lib/media.js';

const MAX_PX = 1568;
const JPEG_QUALITY = 82;

export default defineTool({
  description: `Look at one image by its ref: a chat-image ref like "user_messages/shubham/chat-images/x.jpg", or a file ref like "_media/<uid>/<ts>-<name>" (what you get from schedule(action=send_later, image_ref=…); the kind is read from the file itself).`,
  inputSchema: z.object({
    ref: z.string().describe('The ref to view, e.g. user_messages/shubham/chat-images/x.jpg'),
  }),
  async execute({ ref }) {
    const refs = normalizeRef(ref);
    if (!refs) return { error: `"${ref}" is not a media ref.` };
    try {
      const { bytes, contentType } = await bucketGetBytes(refs.bucket, refs.path);
      const view = await resizeForView(bytes, contentType);
      return {
        type: 'image-content' as const,
        source: { type: 'data' as const, data: view.bytes.toString('base64'), mediaType: view.contentType },
        filename: refs.path.split('/').pop() ?? 'image',
        ref: refs.path,
        note: view.resized ? `Shown at ${view.width}x${view.height} (shrunk to fit).` : 'Shown at original size.',
      };
    } catch (err) {
      return { error: `could not read ${refs.path}: ${err instanceof Error ? err.message : String(err)}` };
    }
  },
});

```

This is the code for the view_image.ts tool that I added. You can see it is pretty simple.

The eve harness is interesting because it allows you to define tools in a way that is very intuitive. It also allows you to define the system prompt in a way that is very intuitive.
