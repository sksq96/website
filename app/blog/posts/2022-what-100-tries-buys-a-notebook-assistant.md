When we see a data science problem, it looks like this.

we are given some data in a table and asked to perform some operation on that table. Or, given some code and a task, we are asked to complete the code.

Now imagine a row of 100 model-generated solutions for a single problem.At some unknown position, one solution is marked as correct, while the rest are incorrect.This is the key idea behind the pass@100 metric:Give the model up to 100 attempts, and see whether it can produce at least one solution that passes the tests.

But here, we are focusing on another question: what does this actually mean for an end user working in a notebook? Suppose I am working in Jupyter and want an AI assistant to help me.We could prompt the model multiple times to generate solutions until one of them works.However, I would then need some way to tell which solution is correct.

For an end user, this is not straightforward.They would need to read the code line by line, or somehow know whether the output is correct.But in this paper, correctness is determined by whether a solution passes a set of unit tests.So perhaps the end user would also need a way to apply those unit tests.

Let us look at the results from the paper.It looks like the model can solve 77.5% of these problems, given 100 tries.Note that this number is not the same as the percentage of correct answers you get if you ask the model to generate 100 answers.So what does this 77.5% actually mean?

You can see more examples in the paper.

I was surprised that the model was able to handle these data science tasks.However, 77.5% is not really the number I care about.Rather, I care about how many tries it takes to get to the right solution.It seems like most of the problems are solved in 20 tries or fewer.

So suppose you are sitting in front of a Jupyter notebook and you want to solve your problem.You have a test case for your problem, and you want to use the model to solve it.You ask the model to generate 20 solutions.What percentage of the time do you expect one of them to be correct?
